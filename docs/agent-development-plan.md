# خطة تطوير الوكلاء والذكاء المحلي — GpTMax

> هذه الوثيقة هي المرجع الرسمي لتطوير قدرات الوكيل البرمجي في تطبيق GpTMax (أندرويد، محلي أولاً).
> تُراجَع بعد كل إصدار فرعي، وتُحدَّث حالة كل مرحلة في الجدول الزمني أدناه.

## المبادئ الحاكمة

1. **الأمان قبل القدرات**: لا تُضاف قدرة جديدة للوكيل قبل إغلاق مخاطر الوصول والكتابة على الملفات.
   هذه الأولوية التي خرجت بها مراجعة الكود الأمنية، وقد نُفِّذت في الفرع `fix/agent-safety`.
2. **الخصوصية محلية أولاً**: الاستدلال والفهرسة والذاكرة تعمل على الجهاز افتراضياً؛ أي مسار سحابي
   اختياري صريح الموافقة ولا يُرسل إلا ما يسمح به المستخدم.
3. **كل قدرة مع قياس**: لا تُعلن قدرة جديدة قبل وجود اختبار JVM أو اختبار جهاز يثبتها، ومؤشر أداء يقيسها.
4. **الفشل آمن**: أي فشل (انقطاع Provider، فشل إعادة تسمية، تعديل خارجي) يُغلق الباب بدل التجاهل،
   مع مجلة تراجع قابلة للاستعادة.

## M0 — الأساس الأمني (منجَز — فرع `fix/agent-safety`)

| البند | الحالة | الملفات |
|---|---|---|
| سياسة مسارات حساسة موحّدة تمنع `.ssh` / `.aws` / `.env*` في القراءة والبحث والفهرسة والكتابة | ✅ | `SensitivePathPolicy.kt` |
| حارس كتابة: قراءة قبل الكتابة، بصمة SHA-256، رفض التعديل الخارجي، مجلة تراجع JSONL، نسخ احتياطية (3 لكل ملف) | ✅ | `FileWriteGuard.kt` + `DocumentTreeWorkspaceTools.kt` + `WorkspaceTools.kt` |
| منع حذف النموذج أثناء تشغيل الوكيل | ✅ | `GpTMaxViewModel.kt` |
| ميزانية سياق الملاحظات (الأحدث أولاً) + مدة التشغيل الكلية | ✅ | `AgentRuntime.kt` |

## M1 — تثبيت الجودة (الأسبوع 1–2)

- اعتماد `docs/proposed/android-build-v2.yml` كمسار CI فعلي:
  - التحقق من Gradle Wrapper (`gradle wrapper` ثم `./gradlew --version`).
  - بوابة `lintDebug` (ناعمة أولاً حتى تصفير التحذيرات القائمة، ثم صارمة).
  - بناء APK release غير موقّع ورفعه كأثر بناء.
- إلزام بنود PR: نجاح `testDebugUnitTest` + `assembleDebug` قبل الدمج في `main`.
- التزام ملفات Wrapper في المستودع (بما فيها `gradle-wrapper.jar` الثنائي) وحذف مسار التنزيل الاحتياطي.

**معيار الإنجاز**: CI أخضر على `main` مع ثلاث بوابات: اختبارات، Wrapper، release.

## M2 — الاختبار على الجهاز الحقيقي (الأسبوع 2–4)

> هذا هو البند المشار إليه في تعليق CI: اختبارات الاستدلال الحقيقية تحتاج محاكياً ونموذج GGUF تجريبي.

- إضافة `androidTest` مع نموذج GGUF مصغّر مرفق (~50MB) في أصول الاختبار.
- سيناريو E2E: استيراد النموذج → جلسة وكيل read-only على مشروع تجريبي → التحقق من النتائج.
- التنفيذ عبر Firebase Test Lab أو محاكي على runner مع GPU، مرتين أسبوعياً + قبل كل إصدار.
- سكربت قياس موحّد يصدّر JSON: رموز/ثانية، زمن أول رمز، ذاكرة الذروة، مدة كل أداة.

**معيار الإنجاز**: تقرير أداء آلي على جهازين على الأقل (متوسط + حديث) لكل إصدار.

## M3 — تطوير قدرات الوكيل (الأسبوع 4–8)

بعد اكتمال M0–M2 فقط:

1. **`file.patch`**: تعديلات موزّعة بصيغة unified diff مع التحقق بالسياق، بديلاً عن إعادة كتابة الملف كاملاً.
2. **محطة أوامر معزولة**: توسيع `ManagedProcessTool` القائم (قائمة سماح + بيئة نظيفة) بموافقة لكل أمر
   عبر مسار `approvalRequest` الموجود، وسجل تنفيذ دائم في مجلة التراجع.
3. **بث الملاحظات**: للنتائج الكبيرة (خرائط الفهرس، مخرجات الاختبار) بث مختصر مع مؤشر للاستدعاء.
4. **التحقق الذاتي**: تشغيل اختبارات المشروع المستهدف بعد كل تعديل وتفسير النتائج قبل الإجابة النهائية.

## M4 — محرك السياق التطوري (الأسبوع 8–12)

- فهرسة رمزية خفيفة (توقيعات الدوال والفئات) بدل مقتطفات نصية.
- ذاكرة بعيدة المدى متجهية محلية (embeddings على الجهاز) لاستدعاء قرارات الجلسات السابقة.
- تلخيص الملاحظات القديمة بدل إسقاطها عند ضغط الميزانية.
- تطوير `PromptContextFit` إلى تدرّج متعدد المستويات (مقتطف → رموز → ملخص).

## M5 — الوضع الهجين الاختياري (الأسبوع 12+)

- مزوّد سحابي ينفّذ نفس عقد `AgentModel`، مفصول تماماً عن الوضع المحلي.
- لا يُفعَّل أدوات الكتابة افتراضياً في الوضع السحابي؛ إشعار صريح لكل عملية إرسال.
- تبديل بين الوضعين دون فقدان نقاط التفتيش أو مجلة التراجع.

## M6 — وكلاء متعاونون (لاحقاً)

- ثلاثية أدوار: مخطط / منفّذ / مراجع، بنفس سجل الأدوات والموافقات.
- لوحة قياس داخلية: رموز/ثانية، زمن الاستجابة، استهلاك الذاكرة، نسبة نجاح الأدوات.

## مؤشرات الأداء المستهدفة

| المؤشر | الهدف |
|---|---|
| إنتاجية الاستدلال (هاتف متوسط) | ≥ 8 رموز/ثانية |
| زمن أول رمز | ≤ 1.5 ثانية |
| جلسة وكيل كاملة (8 خطوات، قراءة فقط) | ≤ 3 دقائق |
| صفر تعديل ضائع (كل تعديل له نسخة احتياطية أو مجلة) | 100% |

## المخاطر والتحوّطات

| الخطر | التحوّط |
|---|---|
| نماذج صغيرة تُنتج JSON غير صالح | `AgentActionParser` متسامح + إعادة محاولة محدودة + إبقاء read-only افتراضي |
| بطء SAF على مجلدات كبيرة | سقوف الفهرس القائمة + فهرس تفاضلي + إلغاء فوري |
| تعديل خارجي للملفات أثناء الجلسة | بصمات `FileWriteGuard` + رفض الكتابة القديمة |
